# 2499 条开发集探索结果

本轮使用 2499 条已观察 MMarco 查询、2496 个查询组，排除了全部已消费确认
ID 和阈值 0.8 的文本近重复。训练特征只来自 raw29 检索特征、当前 BGE
TensorRT 分数、BGE 支持向量和 BM25 查询统计；没有回流 GTE 分数或确认标签。

原 fixed equal-RRF hybrid 基线为 nDCG=0.6265222293、Recall=0.7631719354。

| 严格嵌套 raw28/calibrated40 | 33.2266% | 19.9685% | 1134/1365 | 未测 | Recall 未过线 |
| 严格嵌套非线性 gain gate | 33.5335% | 20.0909% | 133/2366 | 1.0657 | 质量通过，延迟失败 |

2499 条完整 HTTP 质量重放没有发现排名或动作偏差。70% 方案的逐查询配对
分组 bootstrap CI 下界为 nDCG 0.19575、Recall 0.13917；但真实 HTTP
`native-length-router` p95=68.8458ms，原 hybrid p95=60.5350ms，比例
1.13729，超过 1.05。另一套非线性门控在另一轮配对测量中比例 1.06568，
同样失败。48 条延迟查询只用于性能测量，不能替代独立确认。

开发结果尚不足以消费新的确认集：没有一套同时通过质量和 HTTP 延迟门槛。
下一项有充分证据的方向应是降低单次 BGE40 重排成本（短序列引擎需重新生成
分数并嵌套验证，不能直接套用历史 logits），或改进候选召回；不能靠修改基线、
重用旧确认或提高 heavy 预算完成目标。

  Recall+20.0122%，独立重放通过，但HTTP p95=83.5364/55.7253=1.49907，
  不采用。完整HTTP Top28/40、动作、特征、logits及配对CI已独立审计。
- seq160重新评分及严格嵌套raw28/calibrated40结果为Recall+19.8943%，
  尚未通过质量门槛，不进入HTTP或确认；未沿用历史1500条logits。
- 保持原batch20/BGE256模型、70%预算与所有训练权重，测试复用

  输出完全相等，门控/排序线程控制及预测合计均值4.3550ms降到1.7772ms。
  组件加速不代表HTTP通过；全量HTTP重新验证中。

无新确认标签被读取，目标未完成，服务器保持运行。

## CPU 优化与输入等价缓存的实际结果

- 复用线程库控制器并使用精确同分规则的dense topk：真实HTTP p95
  64.5651/60.0802=1.07465；完整2499回放与canonical logits误差为0，
  仍未达到1.05。
- 文档token缓存已核对169,932个输入对，IDs/masks/模板/截断完全相等，
  无query预测缓存。实际HTTP p95降到63.0146ms，但同轮原hybrid为
  56.2946ms，比例1.11937，仍失败。没有为挑选有利结果而重复相同测量。
- seq160真实评分的嵌套gain gate达到nDCG+33.9031%、Recall+20.0341%，
  cheap/heavy=105/2394，独立模型/门控/CI重放通过，正在运行真实HTTP。
  同一seq160的70%预算版本Recall+19.9554%，不能进入HTTP。

最终训练与审计程序已经准备：只有对应HTTP开发门槛通过后，才允许在全部
开发组上重新选型、拟合两个最终模型并独立重训核对；不能复制fold0。
