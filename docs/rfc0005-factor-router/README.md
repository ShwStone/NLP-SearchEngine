# DuReader 重排预算实验

在同一组 730 条查询、相同的 100k 索引和 21,676 个 CE pairs 上，完整语料训练的收益分解 Router 得到 **0.437219 nDCG@10**。可先读取 CE-28 分数的 PR #9 原 26 特征探针作为额外信息参考，得到 **0.426951**。仅用 100k 开发数据训练时，两者分别为 **0.430534** 和 **0.432484**。小数据实验不足以断言哪种方法更好。

## 决策算法

给定一批查询和允许升级的名额 $K$，Router 要在 CE 打分前决定谁用 CE-40、谁用 CE-28。多给一条查询 12 个 pairs，就少一次升级其他查询的机会。最终算法先用 **teacher–student 蒸馏**给全批查询排一个初始顺序，再用**文档级的收益与损失预测**修正名额边界。下面从训练时能看见的答案讲到推理时实际可用的信息。

### 1. 用事后质量差构造 teacher

令 $Q_d(q)$ 表示查询 $q$ 在固定检索器和深度 $d$ 的 raw CE 排名上的 nDCG@10。训练时可用 qrels 计算真实升级收益 $\Delta_q=Q_{40}(q)-Q_{28}(q)$。例如，新相关文档进前十会增加收益，原榜首相关文档掉到第三会扣除收益，两件事可能发生在同一次升级中。$\Delta_q$ 已经包含两者的净效应。

如果所有查询先做 CE-28、只给 $K$ 条升级，整批相对 CE-28 的质量增量就是所选 $\Delta_q$ 的和除以查询数。teacher 据此把训练查询的 $\Delta_q$ 转成软升级标签。设 $\rho$ 为训练时可升级查询中的名额比例，$u$ 为达到训练质量锚点 CE-33 所需的平均增益。具体计算时，把符合升级条件的查询先置于 CE-28，已有跳过名单的查询置于 CE-0，将这一基线与固定 CE-33 的总质量差除以符合升级条件的查询数。在满足平均升级概率为 $\rho$、期望增益达到 $u$ 的方案中，选对真实收益依赖最少的方案。固定 $\rho$ 时，这等价于让给定收益后的二元决策熵尽量大。两次实际拟合的解都在可行区间内部，形式为

$$
t_q=\sigma(\alpha+\beta\Delta_q),\qquad
\operatorname{mean}(t_q)=\rho,\qquad
\operatorname{mean}(t_q\Delta_q)=u .
$$

这里的 $t_q$ 是预算和质量约束下的**软分配概率**。一个只有极小正收益的查询，和一个能把相关文档提到榜首的查询，会得到不同的监督。8M 冻结 teacher 的 $(\alpha,\beta)$ 约为 $(-1.7312,2.2112)$，由 62,266 条符合升级条件的训练侧查询确定，包含后续的 FIT 和 CAL。查询级 student 的树只在其中 46,654 条 FIT 上拟合。100k 版的 teacher 在 347 条 FIT 上独立求解，参数约为 $(-2.4898,5.6253)$。两组 teacher 均未使用原 730 条报告查询。训练侧的 $\rho$ 服务于生成软标签，报告时的 $K$ 由该次评测的 pairs 预算给定。

### 2. Student 在 CE 之前提名可能改变前十的文档

推理时可见的是 96 个 query/BM25 特征，以及首轮 BM25 前 200 篇文档的次序、局部文本匹配和冻结 BGE 表示。文档向量按 BM25 返回的 ID 查表。BM25 第 29–40 名和 **hybrid 候选池第 29–40 名**可能是不同的文档；后者才是升级后会额外打分的 12 篇。因此，student 必须从前者的可见信息预测后者的资格。

对每篇可见文档 $d$，先估计两个概率。$p_d$ 估计它为已知相关文档的可能性：在 512 维冻结语义向量上学习查询和文档各自的 32 维投影，将投影匹配与原余弦匹配相加，再用留出的训练组做 sigmoid 校准。$m_d$ 估计**文档已知相关时**它位于 hybrid 第 29–40 位的可能性，用局部匹配、BM25 位次和它在本批 BM25 文档内部的语义位次等信息预测。先学相关性可以使用 BM25 前 200 各位置的正例；只盯着后段 12 篇会丢掉大量训练监督。

按 $p_dm_d$ 取最多 8 篇**挑战者**；在剩余文档中按 $p_d(1-m_d)$ 取最多 4 篇**对手**。第二个分数用来寻找可能已经贡献相关性的文档，不能保证它实际在 CE-28 前十。提名时同分沿用 BM25 次序。8 和 4 是封存的提名数，限制了每个查询要比较的文档对数，也使漏提名的收益成为可测的误差来源。[文档提名代码](../../evaluation/ce_factor_model.py)

### 3. 用成对证据得到查询初始分数

对每个“挑战者 × 对手”组合，树模型同时读取两篇文档的匹配特征、若干特征差和两者的向量余弦，最多比较 $8\times4=32$ 对。训练这些比较时，取实际落在新增 12 篇的挑战者和实际进入 CE-28 前十的对手。令 $w(r)=1/\log_2(r+1)$，前十之外取零。训练目标是 CE-40 排名下两篇文档的正折扣优势 $\max(0,w(r_a)-w(r_b))$，其中 $a$ 是挑战者，$b$ 是对手。这一步学习“放在一起谁可能更靠前”；查询层的监督仍是第 1 步的 teacher。

将各对优势按提名资格和相关概率加权，从挑战者、对手两侧各取总量与最大值，得到四个成对特征。它们与 96 项查询特征、BM25 不同排名段的文档概率汇总一起输入查询级 ExtraTrees，回归 $t_q$，得到初始分 $s_q$。拟合行的底层文档预测按查询组折外产生。按 $s_q$ 从高到低排，先给前 $K$ 条 CE-40。到这一步，已经有一个可独立评测的“原提名成对版”。

### 4. 将净收益拆成可监督的排名变化

同一个查询级净差可以由完全不同的排名变化造成。为区分这些情况，训练时把每篇已知相关文档在深度 $d$ 的前十折扣贡献记为 $c_d$，其中包含相关性增益及该查询的 IDCG@10 归一化。相关性按提供的 qrels 定义，无标注的文档可能实际相关。前十外贡献为零；8M 训练的同一已标注正文按评测口径去重。逐正文的 $c_{40}-c_{28}$ 求和得到真实 $\Delta_q$。模型只提名一部分文档，因此不能直接把提名文档的净和当作整条查询的完整答案。

对每个挑战者，实际监督的正向收益为 $\max(0,c_{40}-c_{28})$。修正层在提名后的文档特征、提名次序和成对上下文上分别学习四项：

| 预测量 | 训练标签与含义 |
|---|---|
| $r_i$ | 挑战者是否为已知相关文档。这里用提名后的上下文重新估计相关性，与提名前的 $p_d$ 用途不同。 |
| $b_{ik}$ | 在已知相关的样本中，真实 hybrid 位于前 28、29–40，或前 40 之外的概率。 |
| $e_{ik}$ | 在给定的候选区间内，已知相关文档的前十贡献是否实际增加。前 40 之外的事件贡献取零。 |
| $a_i$ | 只在正向收益实际发生的训练样本上回归正收益幅度。两个有效候选区间共享这一幅度模型。 |

8 篇挑战者的预计总收益是 $\widehat G(q)=\sum_i r_i(b_{i1}e_{i1}+b_{i2}e_{i2})a_i$（区间 1 为前 28 位，区间 2 为第 29–40 位）。实现既允许新文档入榜，也允许已有候选获得更好的名次。对 4 篇对手，则分别回归两类**损失的数值**：跌出前十时损失原有贡献，留在前十但降位时损失两次折扣贡献之差。两类预测对 4 篇求和得到 $\widehat L(q)$。这些辅助模型直接学习训练排名提供的标签。[修正层训练代码](../../evaluation/fit_ce_factor_correction.py)

### 5. 只在名额边界使用新证据

基础 student 分数已经间接包含平均的涨跌影响。若直接在它上面再加 $\widehat G-\widehat L$，会把同一份证据算两遍。在独立于 student 树拟合的 CAL 上，用初始分 $s$ 做一元仿射最小二乘，估计三个同量纲的基准值：整条查询的平均净收益 $N(s)$、这 8 篇提名文档的平均正收益 $G_0(s)$、这 4 篇对手的平均损失 $L_0(s)$（代码分别拟合跌出和降位再求和）。最终分数为

$$
S(q)=N(s_q)+[\widehat G(q)-G_0(s_q)]-[\widehat L(q)-L_0(s_q)] .
$$

如果新模型认为某条查询的挑战者收益恰好等于同初始分查询的平均收益，对手损失也恰好等于平均损失，最终分数就回到 $N(s_q)$。如果它预测的损失特别大，该查询会被下调，即使它有一篇很可能入榜的新相关文档。

修正集中在原升级分界线两侧。730 条报告查询中 $K=103$，取初始优先级第 **79–128 名**共 50 条，按 $S(q)$ 重排，让其中 25 条升级；同分以查询 ID 打破平局。原前 78 名保留 CE-40，原第 129 名起保留 CE-28。这样即使修正有误，也只影响接近分界线的查询。边界宽度是开发阶段冻结的设计选择。在本次报告口径下，成本恒为 $730\times28+103\times12=21\,676$ pairs；固定名额评估不检验逐条在线到达时的独立阈值。[预算分配代码](../../evaluation/ce_factor_router.py)

### 一次真实的决策怎么算

下面取 **8M 分组 TRAIN 留出**的一次分配。为避免按事后成败挑案例，分别在实际换入和换出的查询中取初始名次离分界线最近的一条。该面板有 2,418 个升级名额，边界两侧各取 604 条。表内是模型当时的预测，已舍入；两条查询均不来自 730 条报告集。

| 预测或决策 | 查询 A | 查询 B |
|---|---:|---:|
| 初始名次与动作 | 第 2,419 名，CE-28 | 第 2,417 名，CE-40 |
| 基准净收益 $N(s)$ | 0.03473 | 0.03475 |
| 挑战者预计收益 $\widehat G$ / 同分基准 $G_0$ | 0.02677 / 0.02735 | 0.00690 / 0.02736 |
| 对手预计损失 $\widehat L$ / 同分基准 $L_0$ | 0.00587 / 0.00397 | 0.00084 / 0.00397 |
| 修正分 $S(q)$ | 0.03226 | 0.01742 |
| 边界内名次与最终动作 | 第 405 名，升到 CE-40 | 第 1,086 名，回到 CE-28 |

具体看 A 的第二个挑战者。它原在 BM25 第 23 位。修正层估计其已知相关概率为 0.03121，落在 hybrid 前 28 和 29–40 的条件概率分别为 0.09807 和 0.64450，这两个区间的获益事件概率分别为 0.00597 和 0.83828，条件获益幅度为 0.31374。该文档的预计贡献约为 $0.03121\times(0.09807\times0.00597+0.64450\times0.83828)\times0.31374=0.00530$。8 篇合计才得到表中的 0.02677。

A 的修正分其实也被调低了。它能拿到名额，是因为在同一批查询里，B 等查询被调低得更多。B 的预计挑战者收益远低于同分基准，抵消了它在对手损失方面的优势。事后查这两条的 qrels，二者的实际升级净收益恰好都为零：这个例子展示一次真实决策，也展示预测与实际收益可以不同。整批是否受益要看所有换入和换出查询的差额。[完整研究过程与消融](research.md)

## Issue #13 验收

固定 CE-33 在此面板为 0.451224、24,090 pairs，两种训练设置均满足成本线，但均未满足质量线。8M 方法相对 CE-33 的差值为 −0.014004，按查询区间 [−0.023386, −0.004524]，最低线要求下界至少为 −0.005。100k 方法下界为 −0.028565。默认策略继续使用固定 CE-33。本方法的文档语义表示属于对首轮 BM25 文档的额外表征，超出了仅用普通 BM25 数值统计的窄口径；8M 扩展也单独披露。原 730 面板在早先研究中已多次查看，本次冻结复测的区间只描述该面板的不确定性。[Issue #13](https://github.com/ShwStone/NLP-SearchEngine/issues/13)

## 复现冻结版本

在带项目依赖的仓库根目录执行以下命令。输入为同一批查询的前置特征文件。heads.joblib 与 adapter.pt 必须来自同一训练设置。原 Docker 使用 Python 3.11、scikit-learn 1.3.0、PyTorch 2.0.0+cu117 和 RTX 2080 Ti，适配层以 CUDA FP16 autocast 推理。

```sh
python -m evaluation.ce_factor_model --inputs "$INPUTS" --model-dir "$WEIGHTS/8m" --slots 103 --output depths-8m.npz
python -m evaluation.ce_factor_model --inputs "$INPUTS" --model-dir "$WEIGHTS/100k" --slots 103 --output depths-100k.npz
```

输入 NPZ 使用以下字段。查询按原面板顺序，文档按首轮 BM25 排名顺序，所有方法使用相同 ID。

| 字段 | 内容 |
|---|---|
| ids、q | 唯一查询 ID；每条查询 96 项 float32 前置特征，列顺序见 feature-schema.json |
| v、table | 512 维 query 向量及本批涉及的冻结文档向量表，文档表第 0 行用于补齐 |
| ind、mask、sim | 每条查询最多 200 个文档对应的表索引、有效位置和未量化文档向量计算的余弦相似度 |
| local | 每个位置 9 列，分别为有效标记、标题/正文字符覆盖、标题/正文二元组覆盖、问句是否完整出现在标题/正文、标题/正文规范化长度的 log1p |

若需从封存的 FIT、CAL 中间结果重训最终修正层，使用下列入口。它保留已经折外拟合的语义提名和基础 Router，重新拟合相关性、区间、入榜事件、条件幅度、两类损失及校准系数。完整前置提名权重随独立模型包提供。提交稿没有提供从官方原始语料重建所有历史特征和基础模型的一键入口。

```sh
python -m evaluation.fit_ce_factor_correction --fit "$CACHE/fit.npz" --calibration "$CACHE/cal.npz" --nomination-model "$CACHE/nomination-heads.joblib" --output refit-heads.joblib
```

本次对两种训练设置都重新拟合了 PR #9 探针；打包后的最终 Router 以及从缓存重训修正层的版本，在每组 730 条查询上的动作均逐条与封存结果相同。对各方法涉及的查询和深度去重后，发送 1,199 次真实 HTTP /search 请求。全部 100 位排序与封存排名一致，无 fallback、无错误。路由在请求前按批计算，因此不把这次 HTTP 耗时作为包含 Router 的端到端延迟。仓库仅保存程序、聚合指标和哈希。[汇总 JSON](metrics.json)
